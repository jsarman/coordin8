# Space Read/Take Race + Txn Vote Fail-Safe — PRD

> **Status: COMPLETE (merged to main, 2026-09-05).** PR [#16](https://github.com/jsarman/coordin8/pull/16). Patch generated by Fable, reviewed and thoroughly tested (unit tests, all four examples, live Docker auction-house walkthrough) before merge.

## Goal

Apply and validate a Fable-generated patch closing two correctness gaps:

1. **Space `read`/`take` TOCTOU race** — the blocking path subscribed to the tuple broadcast *after* the initial query/attempt, so a tuple written in that gap could be missed until something else nudged the broadcast. Also, a `Lagged` broadcast error just `continue`d, silently possibly missing a match that had already landed in the store.
2. **TxnMgr vote fail-safe** — `vote_from_i32` defaulted unknown/garbled values to `Prepared` (commit-leaning). Fail-open is the wrong default for a 2PC vote.

## Motivation

Both are the same shape of bug: an ambiguous or edge-case signal being resolved toward the *unsafe* outcome (missed match, or commit) instead of the safe one (re-check, or abort). Same category as the EventMgr subscribe-before-drain decision (`.claude/plans/eventmgr/decisions.md`) — worst case should be "redundant recheck," never "silently wrong."

## Fixes

- Space `read`/`take`: subscribe to the tuple broadcast *before* the initial query/attempt. On `Lagged`, re-query the store instead of continuing, since a match may already be sitting there unseen.
- TxnMgr `vote_from_i32`: only `0` (`Prepared`) and `1` (`NotChanged`) map to non-abort outcomes; everything else — including unrecognized future values — maps to `Aborted`.

## Non-Goals

- Did not touch Space's `Notify`/`watch()` mechanism at all — that's a separate, pre-existing gap (best-effort by design, matches the real Jini spec) tracked as [issue #17](https://github.com/jsarman/coordin8/issues/17), see `session-1-complete.md`.
- Did not touch the DynamoDB provider wiring gap found during this session — tracked in `.claude/plans/hardening-roadmap/PRD.md`.
